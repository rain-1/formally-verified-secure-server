# What is actually proven (and what is not)

The tables identify which properties `make verify` checks with F* and Z3, which come from external verification, and which rely on tests or assumptions.

## HTTP core (`src/Http.*.fst`)

| Property | Status |
|---|---|

| Every key the spec can produce is well-formed: non-empty, only `[A-Za-z0-9._~-/]`, no empty segment, no segment starting with `.` (so no `.`/`..` component) — `Http.Spec.key_of_wf` | **proved** |
| `Http.Core.norm_key` computes exactly `key_of(path_of(target))` when the spec accepts the path, and rejects exactly when it does not | **proved** (functional refinement) |
| `Http.Core.lookup` returns an entry iff its key bytes equal the query key; entry offsets are bounds-checked | **proved** |
| Memory safety / no integer overflow / no out-of-bounds for parser, normalizer, lookup, header builder | **proved** (Low*) |
| Parser: accepted request => target lies inside the header block, `consumed <= input length` | **proved** |
| `Http.Parse.scan_headers` marks the request invalid when it reaches its line budget with headers still to scan. | **proved** |
| Successful `Http.Parse.parse` consumes a header section with at most 100 CRLF-terminated fields and a final blank line. Each field has a nonempty token name and a value made of visible ASCII, spaces, or tabs. Field name matching is ASCII case-insensitive. The section contains exactly one `Host`, rejects every `Transfer-Encoding` field, and permits only a single zero digit surrounded by optional spaces or tabs in each `Content-Length` field. `Http.Server.handle` carries the same guarantee for requests routed to a site entry or to 404. | **proved** |
| For a routed request, the close flag starts unset and is set exactly when any case-insensitive `Connection` field contains the ASCII substring `close` in its trimmed value, using case-insensitive matching. Subsequent fields preserve a set flag. The routing contract carries the flag through to the shell-facing result. | **proved** |
| `Http.Core.lookup` is also **complete**: "not found" means no in-bounds entry has the key | **proved** |
| `Http.Server.handle` routing theorem (`routed`): if it serves a body (`res[8]=1`) the body slice is the site entry whose key equals `key_of(path_of(target))` (target = the bytes the parser identified); if it answers 404 for a parsed request (`res[8]=2`) then either the path is rejected by the spec or no in-bounds entry has that key | **proved** |
| `Http.Server.build_header` serializes the status line, a canonical decimal `Content-Length` for its supplied 32-bit length, the `nosniff` field, `Allow` for 405, and the selected `Connection` field followed by a final blank line. A 200 response includes the exact `Content-Type` line selected for the supplied site key. The returned length is the length of the serialized header. | **proved** |
| `Http.Server.put_ctype` uses the suffix after the last dot in the final path segment. It matches the entire suffix against the media-type table using ASCII case folding. Missing, empty, and unknown extensions yield `application/octet-stream`. | **proved** |
| `Http.Parse.parse` ties the accepted method and target offsets to the literal GET or HEAD request line and HTTP/1.1 version. A complete head ends at the first CRLFCRLF. Without that terminator, the parser reports incomplete below the input limit and oversized at the limit. | **proved**. [Parser contract](../src/Http.Parse.fst#L405) |
| `Http.Server.handle` ties the consumed first head and routing result to the serialized response. A hit reports the selected entry's offset, with its full length for GET and zero body bytes for HEAD. Both methods advertise the entry length and use the same media-type selection. A routed miss emits a 404 with an empty body. Error replies have an empty body and close the connection. | **proved**. The contract leaves the exact 400 versus 405 classification open. [Handler contract](../src/Http.Server.fst#L1211) |

## Assumed (trusted) interfaces

`src/Hacl.*.fst` and `src/EverCrypt.AEAD.fst` declare the contracts of the HACL*/EverCrypt C functions we call (`assume val`).
The SHA-256, HMAC-SHA-256, HKDF, X25519, ECDSA P-256 signing, and ChaCha20-Poly1305 bindings assume the C functions compute the corresponding vendored HACL* specifications. The X25519 contract includes the all-zero check. The P-256 contracts cover successful signatures and modeled signing failure, public-key derivation with private-scalar rejection, and both public point encodings. The vendored X25519 and P-256 C and headers match the pinned upstream release byte for byte, and the contracts follow the upstream verified implementation interfaces. [X25519 binding](../src/Hacl.Curve25519_51.fst) · [P-256 binding](../src/Hacl.P256.fst) · [Upstream P-256 interface](https://github.com/hacl-star/hacl-star/blob/f557259007db9933442dde10aa995c1b00bd3446/code/ecdsap256/Hacl.P256.fsti#L281)

AES-128-GCM sealing and opening use the pinned Vale GCM algorithms specified by the x86-64 wrappers. The TLS adapter proves the lengths of the ciphertext, tag and opened plaintext for a 16-byte key, a 12-byte nonce and a five-byte header. The Vale specification retains axioms for AES round operations and word semantics. The local EverCrypt binding assumes the linked C and assembly follow the model and the backend status contract. With the backend available after EverCrypt initialization, the verified buffer bounds suffice for sealing to succeed and for opening to return success or authentication failure according to the model. Backend unavailability has a separate status. The build and CPU feature configuration are assumed stable. [TLS model](../src/Tls.AesGcm.fst) · [EverCrypt binding](../src/EverCrypt.AEAD.fst) · [Vale sealing interface](https://github.com/hacl-star/hacl-star/blob/f557259007db9933442dde10aa995c1b00bd3446/vale/code/arch/x64/interop/Vale.Wrapper.X64.GCMencryptOpt.fsti#L134) · [Vale opening interface](https://github.com/hacl-star/hacl-star/blob/f557259007db9933442dde10aa995c1b00bd3446/vale/code/arch/x64/interop/Vale.Wrapper.X64.GCMdecryptOpt.fsti#L129)
Vendored C: `csrc/hacl` (commit `f557259007db9933442dde10aa995c1b00bd3446`); vendored F* specs: `third_party/hacl-fstar` (same commit, unmodified).

The F\* ClientHello binding assumes that the C adapter preserves the heap, that a successful result identifies a prefix satisfying `valid_body`, and that a matching prefix yields its exact end offset. The independent C-level evidence covers both directions for the local grammar. The F\* and Lean grammar definitions are matched by review at the interface. [ClientHello evidence](evidence/aristotle-clienthello-validator.md)

## Not verified at all

The Rust shell owns the epoll loop, socket I/O, timeouts, and site snapshot. Its FFI, descriptor-relative filesystem operations, and sandbox syscalls use trusted unsafe wrappers. Functional verification of the shell and its integration with the extracted core remains open. [Trust assumptions](TRUST.md)
